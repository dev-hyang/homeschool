# homeschool

家庭学堂 · 以信仰为中心的在家教育规划与记录。小月亮（baby-log）的姊妹应用：小月亮回答"刚才发生了什么"，家庭学堂回答"接下来做什么、做到哪了"。

纯静态网页，无构建步骤，托管在 GitHub Pages：`https://dev-hyang.github.io/homeschool/`。

## 姊妹应用

小月亮（`baby-log`）、家庭学堂（本仓库）、爱家小助手（`home-pantry`）三个站点同一个账号同一个家庭。站点列表在 `js/core/config.js` 的 `SISTER_APPS`；右上角两枚小标签 ‹ 上一个 / 下一个 › 环绕切换（和小月亮同一布局，连接状态在其下方），底部“我的”页和设置页里也有链接。

底部页签：今天 / 课程 / 资源 / 日历 / 我的。课程、资源、日历都是“入口页 + 子页”：入口页只放几行带摘要的入口（`me.js` 的 `mrow`），子页顶上有“‹ 所属页”返回（`views.js` 的 `PARENT` / `VIEWS`）。课程 → 单元与课时（单元卡默认折叠，只显示下一节）/ 年度范围 / 学习目标；资源 → 日常点子 / 资源库；日历 → 月历留在首屏，周例行是子页（默认只看今天这一天，七个星期片带条数可直接跳，‹ › 翻前后一天，“整周”铺开）。今天页不变。报告、法规、设置、介绍、打印（今日页 / 本周 / 本月）、姊妹应用都收在“我的”（`js/me.js`），宽窄屏一样，不折叠；报告和法规打开后顶上有“‹ 我的”返回。右上角只剩连接状态。

## 与小月亮的关系

- 同一个 Supabase 项目、同一个账号、同一个家庭、同一份孩子列表。两个站点都在 `dev-hyang.github.io` 下，登录会话通过浏览器自动共享。
- 创建家庭的人是家主（`family_members.role = 'owner'`，迁移 009）。家主在设置里可以重置邀请码、改任何成员的称呼（迁移 010 的 `set_member_name`）、把家人设为家主 / 转回成员、移出误加入的人；每个人也可以改自己的称呼。两个站点的设置页都能做，走同一组数据库函数。
- 孩子的名字和生日在小月亮里维护；这里只读。数据库里孩子来自 `children` 表（迁移 002），表还没建时回退到 `families.settings` 的 JSON。
- 数据库脚本（基线 `schema.sql` 加编号迁移）放在 baby-log 本地检出的 `supabase/` 目录，不进 git。本仓库以后新增的表也写成那里的迁移文件，在 Supabase SQL Editor 里手动执行。
- 在线优先：直接读写 Supabase，不做离线队列；本机只存"当前看哪个孩子"和主题。

## 定制流程（`js/flows.js`、`js/data/flows.js`）

资源页第一行，是一个层级：定制流程 → 睡前安然 / 冲突管理 / 以后补充的流程（`data/flows.js` 的 `FLOWS` 里加一项就出现在列表里）。

**冲突管理**：害怕、怕生、不愿分享、抢东西、打人、咬人、发脾气七种状况。每种按孩子现在的年龄段（2 岁前 / 2–3 / 3–5 / 5 岁起，沿用 `stageOf`）解释为什么，再给怎么做、怎么说、不要、经文、什么时候找专业人员；其他年龄段折叠着可看。依据儿童发展的一般共识，只作参考，不是诊断。

**记录怎么回填**（两个方向）：
- 家庭学堂 → 小月亮（自动）：在冲突管理里「记一笔」时，给每个参加的孩子往小月亮 `entries` 写一条 `behavior`（情绪行为：kind 按状况映射为害怕 / 打人咬人 / 发脾气，trigger 是状况名加起因，how 是怎么处理的，minutes 是持续分钟，note 带「来自家庭学堂 · 冲突管理」）。id 固定为 `hscf-<记录 id>-<孩子 id>`，所以改这笔会更新它，删这笔会把它标成已删，去掉的孩子那条也删，不会重复。页面上有开关（`bedtime.mirrorConflict`，默认开）。离线记的先排队，联网补传时一起写。
- 小月亮 → 家庭学堂（只读）：页面读小月亮近 61 天的 `behavior` 和 `social` 记录（RLS 决定看得到哪些），按孩子和状况映射统计近 30 天次数、与上个 30 天对比、平均持续、家里记过的处理办法；「分享合作」是好的记录，单独当亮点显示。读到的不会写回，也不复制。
- 补记：日期选过去的，小月亮那条落在那天中午。
- 记录存在 `hs_bedtime_events`（和睡前的状况记录同一张表，`situation` 以 `cf-` 开头区分，不另建表）。

**二期**：
- **经文全文**：状况卡里的引用经文中英文都抓全文（按设置里的抓取译本，存本机）；抓失败的记住原因、10 分钟内不重试，行内有「再试」。
- **问一问咩咩咩**：每张状况卡一个「不管用？问一问咩咩咩」，带着孩子年龄段、应用自带的做法、家里在这个状况下最近的记录（做法、结果、用时、孩子和大人当时的状态）去问；定制流程页顶上有直接入口和几个话题；趋势页有「让咩咩咩分析最近的记录」。三处用同一份摘要（`flowContext`），咩咩咩页的「会发送什么」里能看到原文；摘要不含孩子姓名和备注，含你写的起因和处理办法。系统提示换成「家庭教养顾问」（原因 / 评价已试的做法 / 接下来 2–3 条 / 给家长的提醒；不体罚不羞辱）。
- **自定义状况**：「自定义状况」写名字和一句话，点「让咩咩咩补全」按孩子年龄段生成为什么、做法、怎么说、不要、经文、何时找专业人员，并从小月亮「情绪行为」的七类里选一类作为回填类别（补出来的都能改）。存在 `hs_family.settings.bedtime.situations`（id 以 `cf-` 开头），记一笔时按这个类别写进小月亮。
- **记录的日期筛选**：冲突管理、睡前状况、睡前每晚的记录都有「今天 / 本周 / 近 2 周 / 本月 / 近 3 个月 / 全部」（由近到远），可在列表和时间线之间切换（时间线按天分组）。
- **大人和孩子两方面**：记录里加「孩子当时的状态」「大人当时的状态」（睡前每晚也有）。需要数据库迁移 020（`child_state` / `parent_state` 两列，两张表）；没执行时这两项自动折进备注，不丢，页面上有提示。
- **趋势与分析**（定制流程下的子层级）：近 7 / 14 / 30 / 60 天。入睡时间、起床时间（读小月亮的睡眠记录，做了睡前流程的晚上是实心点，虚线是平均）、做了 vs 没做的对比（入睡、起床、每天冲突次数）、睡前流程完成、冲突次数与结果、大人的状态、孩子的状态。每个图都有数字或提示和文字图例。

## 多语言：应用自带内容（五期）

界面文字（按钮、标题、提示）一直走 `t()`；这一期补的是「应用自带的内容」，它们要么存进数据库后是中文原文（周例行模板的标题、睡前流程的步骤名和带领词……），要么写在数据文件里（读经计划、大原则、冲突 / 情绪管理……）。

- **机制**：`core/i18n.js` 里有一张「中文原文 → 英文」表（`addContent`）。`tc()`（显示应用自带内容）在英文界面查这张表，再查界面字典；`tb()`（显示存进数据库的模板内容）同理，繁体界面只对表里有的内容转繁体，用户自己输入或改过的原样显示，不被翻译或转换。圣经出处（`创世记 12; 15`）在英文界面自动换成英文书卷名（`bible.js` 的 `refEn`，`setRefFormatter` 登记）。没有英文的内容照原样显示中文，不报错。
- **登记**：`data/content-en.js` 在应用启动时把英文对齐到中文数据（按字段、按数组下标；`CONTENT_STATS.orphans` 列出对不上的字段，应为空）。英文放在 `data/en-flows.js`（冲突 / 情绪管理，按 id 对应）和 `data/en-content.js`（周例行模板、读经计划、大原则、睡前安然、推荐歌曲、姊妹应用简介）；结构和中文数据完全一致，改中文内容时在这里同步改英文。
- **显示点**：任务 / 周例行标题（今天页、日历、打印）、流程和步骤名、带领词、读经出处、经文默认语言（没明确选过就跟界面语言走）等已接上 `tb()` / `tc()`。
- **课程库等内容库的英文**：`data/en-curriculum.js`（课程库，另含按规则生成的固定格式：字母课、三字经课号、词族、常见词）、`en-library.js`（起步课程 / 目标 / 资源 / 参考来源）、`en-ideas.js`（日常点子）、`en-law.js`（各州法规摘要，法律摘要翻译请逐条核对）、`en-about.js`（介绍页与成套经文说明）。这几份键是中文原文，值是英文，由 `content-en.js` 登记；固定格式的规则用 `addRules` 登记。课程、单元、目标、资源等存进数据库的标题显示时用 `tb()`。改中文内容时同步改这里的英文，否则英文界面显示中文。

## 大原则、年龄段与情绪管理（三期）

- **大原则**（`js/principle.js`、`js/data/principle.js`）：按神的恩典慈善管教，把圣经的价值完整地教导给下一代，使他们行神所当走的路，不偏离左右。今天页最上面一张「我们的根基」卡（默认展开，收起记在本机），其余各层（课程、资源、日历、我的、定制流程、睡前、冲突、情绪、趋势、咩咩咩）顶上一行小字，点开是同一份；冲突、情绪、睡前状况和播放页的「遇到状况」里有常驻的「怒气来的时候」卡；咩咩咩的系统提示末尾也带上这条原则。
- **自动同步小月亮**：每次打开带「从小月亮重新读取」按钮的页面（冲突管理、情绪管理、趋势与分析），先在后台拉一次（`flows-trend.js` 的 `beforeRender` → `pull`）；拉的时候按钮灰色不可点，拉完提示「已同步最新小月亮记录（n 条）」，按钮旁写上次同步时间；停在页面上、小月亮那边又有新记录时可再点按钮手动拉；离开这几页再回来会再自动拉。读的类型：情绪行为、社交、睡眠、情绪、自律、活动（屏幕），近 61 天，只读。
- **按年龄段和性别**：年龄段分六档（2 岁前 / 2–3 / 3–5 / 5–8 / 9–12 / 13 岁起，`data/flows.js` 的 `bandOf`）。每种状况有各档的常见程度 `rel`、解释 `why`，做法 `steps` / 怎么说 `say` 可按档覆盖（`byBand`，9–12 没写回退 5–8，13 岁起回退 9–12）；页面把这个年龄段常见的放前面，较少见的折叠在「这个年龄段较少见」里（例如 6 岁很少咬人）。新增「顶嘴、不服从」「排挤、说闲话、冷战」两种大孩子的状况。性别（可选）放在家庭学堂设置里按孩子单独记（`hs_family.settings.genders`，小月亮里没有这一项），用来决定青春期话题给谁看、显示一句「平均而言」的性别提示；不设置就都按年龄段显示。
- **情绪管理**（`js/data/emotions.js`，页面在 `flows.js`）：嫉妒、焦虑、厌学、屏幕（使用规则：爸爸妈妈先在孩子不在场时商量、写成家庭屏幕协议、以身作则、无屏幕时间和地方、内容把关、用价值观解释；附年龄建议表）、成瘾 vs 癖好（对照表 + 步骤）、时事、女孩 / 男孩的生理发育（含爸爸的心理准备）。和冲突管理分工：冲突讲「一件事发生了当场怎么办」，情绪讲「持续的情绪和习惯平时怎么陪伴」。情绪管理的记录（`em-` 开头）只存在家庭学堂，不写进小月亮。

## 歌单手势、多流程与推荐歌曲（四期）

- **歌单行手势**（`js/songs-ui.js`）：每首歌只保留「播放」和最右边的 ⋮⋮，去掉了上下移动按钮。手指向左滑露出红色「删除」（滑过约三分之一行宽松手，先确认）；手指向右滑露出蓝色「加到流程」（松手打开选择页）；长按 ⋮⋮（约 0.4 秒，手机轻震）这一行浮起，上下拖动调顺序，松手保存（逐个更新 `sort`）。键盘 / 读屏：⋮⋮ 上按 ↑ ↓ 移动，歌曲编辑页里有「加到流程…」和「删除」按钮。左滑删除和应用里其他列表一致。
- **加到流程**（歌单行左滑 / 编辑页按钮）：选择页里列出睡前安然的每个流程的每一步（一步只放一首歌，点一下放入、再点取消，会换掉原来那首），以及冲突管理、情绪管理的每个话题（可放多首推荐歌，存在 `bedtime.topicSongs`）。
- **睡前安然多流程**：可以建多个流程（晚觉 20 分钟、午睡 8 分钟、起步版、自己的），每个有名字、类型（night / nap）和自己的步骤；新建时可从模板（完整版 / 起步版 / 午睡版 / 空白）开始。开始前在今天页的「睡前」一行、睡前页、流程页顶上选流程（选择只记在这台设备，不写云端）。老数据里单个步骤列表自动变成第一个流程「晚觉」。完成记录在每步里带上流程名和类型，午睡不算「晚上做了睡前流程」（不进趋势里的对比），回写小月亮时写流程名。
- **推荐歌曲**（`js/data/music.js`）：冲突管理、情绪管理的每张话题卡有「推荐歌曲」：按情况建议是哪一类（经文类 / 被爱与安慰类 / 舒缓 BGM；事发当时优先舒缓、不说教的纯音乐，经文歌和被爱的歌放在平时和修复关系时），列出可以找的歌（没把握的不写具体曲名）；再列已加到这个话题的歌（可试听、可移除），和歌单里带这一类标签的歌（最多三首）；卡上「从歌单加」也能挑歌。
- 修了一个老问题：全新家庭的默认步骤每次读取配置都生成新的随机编号，没保存过之前点步骤会对不上；现在默认步骤用固定编号。

## 睡前流程步骤的手势

流程页的步骤行和歌单行共用 `js/songs-ui.js`：去掉 ↑↓ 按钮，改成长按最右边的 ⋮⋮ 拖动调顺序（键盘上 ⋮⋮ 按 ↑ ↓ 也行），手指向左滑删除（先确认）；步骤行向右滑不动。步骤的 ↑↓ 以外的编辑（点一步改名字、分钟、歌、文字）不变。

## 睡前安然（`js/bedtime.js`、`js/bedtime-play.js`、`js/data/bedtime.js`）

以诗篇 4:8 为中心的睡前敬拜流程，解决的是「孩子不好好睡、管教后又自责」：安抚多过刑罚，不等于不管教。入口在今天页最下方的卡片和「我的」。

- **流程**：五步模板（收拾转换 3 分 → 拥抱与敬拜 4 → 读诗篇 4:8 3 → 修复关系与祷告 5 → 音乐与安睡 5）和三步起步版（约 8 分钟）。每步可改名、改分钟、选歌（指定一首或按「被爱 / 神的话 / 休息」标签挑）、选显示哪段文字、跳过。合计超过上限（默认 30 分钟）标红提醒，不拦。
- **播放页**：整页深色、字大、只有「下一步」；不显示封面和歌词（父母要跟唱才点开）。每步一条细进度条 + 「约 n 分钟」，到时震一下、进度条变色，不响铃、不自动跳步；只有最后一步（循环）到时音乐 10 秒淡出，进入「今晚完成」。Media Session 让锁屏后继续放、锁屏上能暂停 / 下一步。「遇到状况」面板里有原则提醒、每种状况的做法和话，可以当场「记一笔」。
- **歌单**：自家的 MP3 / M4A 传到共用 Supabase 项目的私有 `media` 桶（迁移 019，单首 20 MB，家庭成员读写）；每台设备第一次播时下载并存进 IndexedDB，之后离线也能放。歌词可手填或「让 AI 补词」（用咩咩咩里的 key，标「AI 补的词」直到核对）。
- **带领词**：内置「家庭通用版」（开场、读经引导、祷告词、结束的话）。新建版本后随意改、可多版（幼儿版 / 学龄版 / 英文版），播放前选用哪版，每版可恢复成模板。
- **睡前经文**：十二段推荐（各带一句给父母的引导、一句问孩子的）+ 自家加的；诗篇 4:8 每晚先读（可关），再选一段今晚的。正文按设置里的抓取译本取，存本机。
- **状况与应对**：八种常见状况模板（不肯睡反复下床、打人抢玩具、说自己是坏孩子、父母发脾气、拖延、怕黑、兄弟姐妹打闹、涉及安全的严重事）各有推荐做法、可以这样说、不要、经文提醒，可改可加。每次发生记一笔（谁、怎么处理、几分钟、结果、值得继续用）；卡上显示近 30 天次数与上个 30 天的对比、平静下来比例、平均分钟，以及标了「值得继续」的做法。顶上是核心原则和箴言 13:24、以弗所书 6:4。
- **记录**：每晚一条（孩子、谁带、版本、经文、歌、计划 / 实际分钟、备注），进日历（金色点）和报告（「睡前安然 n 晚」）；可补记。开着「回写小月亮」时给每个参加的孩子写一条「信仰 · 家庭敬拜」记录（小月亮信仰模块打开才看得到），睡眠记录旁就能对照。
- **离线**：配置和歌单在本机留一份，没连上云端也能开播放页；完成记录和状况记录先排队，联网后自动补传。
- **开始睡 / 唤醒**（`js/wake.js`）：完成睡前流程（晚觉或午睡）时，给每个参加的孩子在小月亮的 `entries` 里写一条睡眠（入睡 = 流程结束时间、自主入睡、没有醒来时间 = 在睡；id 固定为 `hsbt-sl-<记录 id>-<孩子 id>`，不会重复；小月亮里已经在睡的孩子、补记的老记录不写）。今天页「睡前」那一行变成 😴「在睡 · 已睡 x」+「唤醒」；所有孩子都在睡时不再显示「开始」。点「唤醒」记下醒来时间（默认现在，可改）、怎么醒（自然醒 / 被叫醒）、怎么入睡、在哪儿睡、备注；「改」可以补记 / 修改 / 删除，改的就是小月亮里同一条（保存前先读最新再合并，不覆盖那边刚改的）。睡着的孩子不管是这里开的还是小月亮里点「开始睡」开的都认（读近 48 小时没有醒来时间的睡眠），也订阅了 entries 的实时变化。睡前页「设置」里可关「完成后记下开始睡」。睡前播放页「谁参加了」默认是今天页「参加」里点选的孩子，没点过就是顶上选中的那个孩子（不再默认全部孩子）。唤醒歌：歌单里给歌勾「轻柔唤醒」，在睡的那一行点 ♪ 一键放（多首轮流）。歌单入口放在「定制流程」页（睡前、冲突、情绪、唤醒共用）。唤醒时可以放歌单里标了「轻柔唤醒」的歌（音量 30 秒从很小升到 0.5），没有歌时列出推荐（晨曦、Morning Has Broken、你的信实广大等）。不需要新的数据库迁移。
- **一步多首歌**：步骤编辑页「放哪些歌」是按标签分组的多选下拉框（勾组名 = 按标签从歌单挑，勾具体的歌 = 就放这首，轻柔唤醒标签不出现在这里）。数据是步骤的 `songs` 数组（歌 id 或 `tag:标签`），`song` 始终等于第一项，老数据照常读；播放页从选中的里面轮流挑，「换一首」循环。
- 配置（步骤、版本、经文清单、状况模板、上限、开关）在 `hs_family.settings.bedtime`；表和桶在 baby-log 本地 `supabase/migrations/019_bedtime.sql`。

## 云盘备份

> 详细的设置步骤（Google Drive 的 Client ID / API Key、Dropbox 的 App key 和 Redirect URI、本地文件夹、数据库重建、排错）见 [docs/backup-and-sync.md](docs/backup-and-sync.md)。

「我的 → 备份与恢复」可以把家庭学堂的数据定时备份到 Google Drive / Dropbox（手机电脑都能用）、电脑上的云盘同步文件夹、共用 Supabase 项目的存储（baby-log 迁移 017）或直接下载。Google Drive / Dropbox 要在 `js/core/config.js` 填两个公开的客户端标识（不是密钥）：

- Google Drive：Google Cloud Console → APIs & Services → 启用 Google Drive API → OAuth 2.0 客户端（类型 Web 应用），「已获授权的 JavaScript 来源」填站点地址，Client ID 填到 `GOOGLE_CLIENT_ID`。权限只有 drive.file（只看得到这个应用自己建的文件）。
- Dropbox：Dropbox App Console → Create app → Scoped access，Access type 选 **App folder**，Permissions 勾 `files.content.write` / `files.content.read` / `account_info.read`，Redirect URIs 填站点地址（带结尾的 /），App key 填到 `DROPBOX_APP_KEY`。
- 备份放在卡片里填的路径下：Drive 默认「家庭学堂备份」（可多级，不存在就逐级建）；Dropbox 是应用文件夹里的子路径。令牌存本机 localStorage，「断开」会吊销并清掉。代码在 `js/cloud-drives.js`，四个应用共用同一份。
